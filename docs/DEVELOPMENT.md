# Разработка и сборка

[← README](../README.md)

## Среда

Node.js 22.14 или новее, npm и Git. CI использует Node.js 24. Версии зависимостей зафиксированы в `package-lock.json`.

```sh
npm ci
npm start
```

Первый `npm ci` скачивает исполняемую среду Electron. Для обычного запуска готового приложения Node.js не нужен.

## Где что находится

| Путь                       | Назначение                                                     |
| -------------------------- | -------------------------------------------------------------- |
| `src/main/index.cjs`       | Создание окон, IPC, файлы данных, звуки, системный значок      |
| `src/main/preload.cjs`     | Ограниченный мост `window.timer` между интерфейсом и main      |
| `src/shared/schedule.js`   | Формат расписания, проверка, выбор текущего состояния и звонка |
| `src/shared/time-input.js` | Ввод времени, вставка, каретка и удаление цифр                 |
| `src/renderer/editor/`     | Главное меню и недельный редактор                              |
| `src/renderer/widget/`     | Плавающий таймер                                               |
| `assets/icons/`            | PNG, ICO, ICNS и значок трея                                   |
| `assets/sounds/`           | Три коротких встроенных WAV-звонка                             |
| `tests/unit/`              | Расчёты, ввод, IPC и регрессии размера окна                    |
| `tests/ui/`                | Проверки реального HTML-интерфейса через Playwright            |

Браузерные окна работают с `contextIsolation: true`, `sandbox: true`, `nodeIntegration: false`. Не добавляйте прямой доступ к Node.js в renderer. Выбор файлов и запись настроек выполняются в main. Внешняя навигация и новые окна заблокированы, ресурсы интерфейса локальные.

`schedule.js` и `time-input.js` доступны и через CommonJS, и в обычном браузере. Это позволяет проверять логику без запуска Electron.

## Проверки

```sh
npm test
npm run check
npx playwright install chromium
npm run test:ui
```

На чистом Linux может потребоваться `npx playwright install --with-deps chromium`.

Unit-тесты проверяют точные границы уроков, перемены, недельный переход, ручной день, ошибки данных, сигналы после сна, импорт/экспорт и ввод времени. Для регрессии компактного вида модель окна воспроизводит ограничение Electron: `setSize` не уменьшает фиксированное окно, а `setBounds` изменяет границы.

UI-тесты используют реальную разметку renderer и тестовый IPC-мост. Они проверяют ввод, сохранение, копирование дней, ошибки пересечений, выбор звука и размещение компактного окна. Они не заменяют проверку системного звука, установщиков и поведения поверх окон на Windows/macOS.

Для теста с уже установленным Chrome задайте `CHROME_PATH` — полный путь к исполняемому файлу Chrome. Например, в PowerShell:

```powershell
$env:CHROME_PATH = 'C:\Program Files\Google\Chrome\Application\chrome.exe'
npm run test:ui
```

## Скриншоты

```sh
npx playwright install chromium
npm run screenshots
```

Скрипт создаёт четыре PNG в `docs/images/`: редактор, урок, перемену и компактный вид. Используются фиксированные демонстрационные данные, дата и русская локаль. Пользовательское расписание не читается. Снимки получаются из настоящего renderer, а не генератора изображений. После изменения интерфейса переснимите их и добавьте в коммит.

## Установщики

```sh
npm run build:win
npm run build:mac
npm run build:mac:intel
```

Выходная папка — `dist/`, она исключена из Git. Настройки находятся в `electron-builder.yml`.

| Сборка      | Результат                                        |
| ----------- | ------------------------------------------------ |
| Windows x64 | Мастер установки NSIS `.exe` и переносной `.zip` |
| macOS arm64 | `.dmg` и архив `.zip` для Apple Silicon          |
| macOS x64   | `.dmg` и архив `.zip` для Intel                  |

Для быстрой проверки без создания установщика используйте `npm run pack:win` или `npm run pack:mac`.

Собирайте Windows на Windows, macOS на Mac. В Actions для этого подготовлены отдельные машины. macOS по умолчанию получает локальную ad-hoc подпись, а не доверенный сертификат Apple. Подписанные и нотариально проверенные публичные релизы требуют собственных сертификатов и отдельной настройки секретов CI. Текущая конфигурация их не требует и ничего автоматически не публикует из локальной сборки.

Не меняйте `appId` или имя `LessonTimer` без плана миграции: это может повлиять на обновление установщика и расположение пользовательских данных.

Для ad-hoc подписи Mac отключён сетевой timestamp (`timestamp: none`). При переходе на сертификат Developer ID настройте доверенную подпись, timestamp и нотариальную проверку отдельно. В package.json также закреплены совместимые исправленные версии `minimatch` для инструментов сборки; это не зависимости работающего приложения.

## Формат данных

Настройки хранятся в `schedule-v2.json` внутри каталога `app.getPath('userData')`. Дни — `mon`, `tue`, `wed`, `thu`, `fri`, `sat`, `sun`. Урок — объект `start`, `end`, `name`. Время — `HH:mm`, занятия должны укладываться в один день. Расписание сортируется и проверяется перед записью.

Пользовательский звук копируется в `custom-sound`. JSON экспорта может содержать его Base64-представление. Не добавляйте личные экспорты в Git: имя файла или название занятия могут раскрывать сведения о пользователе.

## Оформление и обновления

`src/shared/appearance.js` строит CSS-переменные для обеих тем и обеспечивает контраст текста при любом акценте. Нативные размеры окна находятся в `src/shared/window-layout.js`, настройки панели Mac — в `src/main/overlay.cjs`.

`src/main/updater.cjs` обращается к публичному GitHub Releases API без токена. Выбирается только более новый стабильный релиз, точное имя файла под платформу и архитектуру и `SHA256SUMS.txt`. До запуска установщика проверяются размер и SHA-256. Windows использует флаги NSIS `--updated /S --force-run`; переносные сборки обновляются вручную.

На Mac ZIP распаковывается во временную папку данных приложения. Проверяются bundle ID, версия и целостность подписи `codesign`. Отдельный помощник `mac-install.cjs` ждёт выхода старого процесса, сохраняет предыдущую `.app`, заменяет её и запускает новую. Подтверждение приходит после загрузки окна редактора; без него выполняется откат. Стандартный Squirrel.Mac здесь не используется: текущие сборки имеют ad-hoc подпись, без постоянной доверенной идентичности Developer ID. Контрольная сумма и ad-hoc проверка не заменяют доверенную подпись издателя.

`tests/unit/updates.test.js` проверяет повреждённые загрузки, отмену, неподходящие релизы, отсутствие прав, запуск установщика и реальную замену/откат в изолированной временной папке. Тесты помощника не меняют установленное приложение и пропускаются на Windows.
