# Как опубликовать проект на GitHub

[← README](../README.md)

## Оформление репозитория

Репозиторий проекта: **[egorca05/LessonTimer---](https://github.com/egorca05/LessonTimer---)**.

Описание для поля **About / Description**:

> Плавающий таймер уроков и перемен для Windows и macOS: расписание на неделю, настраиваемые звонки и компактное окно поверх приложений.

Topics: `electron`, `education`, `schedule`, `countdown`, `desktop-app`, `windows`, `macos`.

Лицензия исходников — MIT. Включена в корень проекта. При желании можно заменить общее указание `LessonTimer contributors` в LICENSE и package.json на выбранное имя автора до первого публичного коммита.

## Первая загрузка

1. Создайте на GitHub новый репозиторий `lesson-timer` с видимостью **Public**.
2. Не добавляйте автоматически README, лицензию или `.gitignore` — они уже есть в проекте.
3. Откройте терминал в папке проекта и выполните команды ниже, используя адрес репозитория проекта.

```sh
git init -b main
git add .
git commit -m "Prepare LessonTimer 2.1.0 for public release"
git remote add origin https://github.com/egorca05/LessonTimer---.git
git push -u origin main
```

Если Git впервые просит имя и email автора, укажите свои данные. Для скрытия личного адреса можно использовать свой адрес `noreply`, показанный GitHub в Settings → Emails. Не нужно публиковать токены доступа в файлах проекта.

Если `origin` уже настроен, проверьте его через `git remote -v`; повторно добавлять его не нужно. Если Git уже инициализирован, команду `git init` можно пропустить.

## Что загрузить

Команда `git add .` учитывает `.gitignore`. В репозиторий попадут исходники, документация, скриншоты, лицензия, lock-файл и настройки CI. `node_modules`, `dist`, установщики и пользовательские настройки игнорируются.

Не загружайте установщики в обычные папки Git. Для них используется **Releases**. GitHub также автоматически создаёт архив исходников для тега.

## Первый релиз

Для автоматической публикации после успешных проверок используйте release-ветку:

```sh
git push origin main:release/v2.1.0
```

Это запустит UI-проверки, сборку Windows и двух архитектур Mac, затем опубликует установщики и контрольные суммы в Releases. Альтернативный способ через тег ниже создаёт только черновик для ручной проверки.

После загрузки убедитесь, что workflow **Checks** завершился успешно. Затем создайте тег:

```sh
git tag v2.1.0
git push origin v2.1.0
```

Workflow **Build installers** соберёт Windows x64, Mac Apple Silicon и Mac Intel. После успешной сборки появится **черновик релиза** с файлами и SHA-256. Проверьте его, затем нажмите **Publish release**. До этого шага черновик не является публичным скачиванием.

Для пробной сборки без тега откройте Actions → Build installers → Run workflow. В этом случае файлы сохранятся как artifacts запуска, а релиз не создаётся.

## Публичная страница

README и изображения уже используют относительные пути. После загрузки скриншоты будут отображаться автоматически. Не требуется менять ссылки на логин автора: кнопка «Скачать» ведёт в Releases текущего репозитория.

В разделе About добавьте описание и Topics. После публикации первого релиза можно закрепить его и указать поддерживаемые платформы в описании.
