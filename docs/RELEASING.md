# Выпуск новой версии

## Автоматическая публичная публикация

Чтобы после проверок сразу опубликовать установщики версии 2.1.0, отправьте текущий коммит в release-ветку:

```sh
git push origin main:release/v2.1.0
```

Имя release-ветки должно совпадать с версией package.json. Сначала проходят UI-проверки, затем собираются три платформы. После успешной сборки GitHub Actions создаёт публичный релиз и тег `v2.1.0`. Уже опубликованные файлы повторный запуск не перезаписывает. Обычный push в main сам по себе релиз не публикует.

## Выпуск через черновик

[← README](../README.md)

1. Измените версию через `npm version patch --no-git-tag-version` (или `minor` для новой функциональности). Это обновит package.json и lock-файл согласованно.
2. Обновите CHANGELOG.md и `docs/RELEASE_NOTES.md`.
3. Выполните `npm test`, `npm run check` и `npm run test:ui`.
4. Если менялся интерфейс, выполните `npm run screenshots` и добавьте PNG в коммит.
5. Проверьте собранные программы на целевых системах.
6. Закоммитьте изменения, отправьте ветку, создайте тег, совпадающий с версией package.json.

Для версии 2.1.0:

```sh
git add .
git commit -m "Release 2.1.0"
git push
git tag v2.1.0
git push origin v2.1.0
```

Workflow проверяет соответствие тега версии, затем запускает сборки на Windows и двух архитектурах Mac. Права записи используются только отдельным заданием создания черновика релиза; собственный PAT для обычного запуска не нужен. Локальные команды сборки всегда используют `--publish never`.

В черновик попадают установщик Windows, переносные ZIP, DMG для Mac и `SHA256SUMS.txt`. До нажатия **Publish release** проверьте:

- установку и удаление Windows без удаления расписания;
- первый запуск и перетаскивание .app на Mac;
- переходы урок → перемена → урок и звуки;
- компактный вид после запуска в обоих режимах;
- сохранение, экспорт и импорт между системами.

Это проверка реального релиза. Автоматические тесты интерфейса не проверяют воспроизведение через динамики и поведение окон поверх других нативных программ.

Если повторно запустить workflow для существующего черновика, файлы в нём обновятся. Опубликованные релизы workflow не перезаписывает: для исправления выпускайте новую версию и новый тег.

Проверить скачанные файлы можно командой `shasum -a 256 -c SHA256SUMS.txt` на Mac или `Get-FileHash <имя файла> -Algorithm SHA256` в PowerShell. Контрольная сумма проверяет целостность файла и не заменяет цифровую подпись издателя.
